## 1. 项目概述

熙心健康体检管理系统是一套覆盖体检业务全流程的数字化管理平台，面向**体检用户（C端）**、**医护人员（B端）** 和**运营管理者（B端）** 三类用户群体，提供从在线预约、科室流转、结果录入审核到报告生成、健康管理的端到端闭环服务。

### 1.1 系统端口一览

| 端口 | 代号 | 技术栈 | 访问方式 | 目标用户 |
|------|------|--------|----------|----------|
| 后端 API | `backend` | Java 17 + Spring Boot 3.3.5 | REST API /api/v1/* | 所有前端调用的后端服务 |
| 管理端 | `admin` | Vue 3 + Element Plus + ECharts | Web 浏览器（PC） | 系统管理员、运营管理员 |
| 医护端 | `staff` | Vue 3 + Element Plus + ECharts | Web 浏览器（PC/平板） | 护士、体检医生、审核医生 |
| 用户端 Web | `user-web` | Vue 3 + Chart.js | Web 浏览器（PC/H5） | 普通体检用户 |
| 用户端 App | `user-app` | UniApp（Vue 3） | iOS/Android/微信小程序 | 普通体检用户 |
| 心电网络系统 | `ecg-system` | Vue 3 + Element Plus（骨架） | Web 浏览器 | 心电图室医生 |

### 1.2 用户角色体系

| 角色编码 | 角色名称 | 所属端 | 职责 |
|----------|----------|--------|------|
| `NORMAL_USER` | 普通用户 | C端 | 浏览套餐、预约体检、查看报告 |
| `NURSE` | 护士 | B端 - 医护 | 签到登记、体征测量、采血、排队导诊 |
| `EXAM_DOCTOR` | 体检医生 | B端 - 医护 | 各科室检查结果录入 |
| `EXAM_DOCTOR_LAB` | 检验科医生 | B端 - 医护 | 检验科结果录入（EXAM_DOCTOR子角色） |
| `EXAM_DOCTOR_IMAGING` | 影像科医生 | B端 - 医护 | 影像科结果录入 |
| `EXAM_DOCTOR_BLOOD` | 采血医生 | B端 - 医护 | 采血 |

## 2. 系统总体架构

### 2.1 架构模式

系统采用 **前后端分离 + B/S架构**，按"表现层 - 应用层 - 数据层 - 基础设施层"四层组织。

```
┌──────────────────────────────────────────────────────┐
│                    表现层 (Presentation)               │
│  ┌──────────┐  ┌──────────┐  ┌────────┐  ┌────────┐ │
│  │ Admin    │  │ Staff    │  │User-web│  │User-app│ │
│  │(Vue 3)   │  │(Vue 3)   │  │(Vue 3) │  │(UniApp)│ │
│  └────┬─────┘  └────┬─────┘  └───┬────┘  └───┬────┘ │
│       │              │            │            │      │
│       └──────────────┴────────────┴────────────┘      │
│                        │ HTTP REST                    │
├────────────────────────┼──────────────────────────────┤
│                    应用层 (Application)                 │
│  ┌────────────────────────────────────────────────┐   │
│  │         Spring Boot 3.3.5 + Spring Security    │   │
│  │  ┌──────┐ ┌──────┐ ┌──────┐ ┌──────┐ ┌──────┐ │   │
│  │  │预约  │ │体检  │ │结果  │ │报告  │ │权限  │ │   │
│  │  │服务  │ │流程  │ │审核  │ │生成  │ │认证  │ │   │
│  │  └──────┘ └──────┘ └──────┘ └──────┘ └──────┘ │   │
│  └────────────────────────────────────────────────┘   │
│                        │ JPA / JDBC                    │
├────────────────────────┼──────────────────────────────┤
│                    数据层 (Data Layer)                  │
│  ┌────────────────────────────────────────────────┐   │
│  │   MySQL 8.0 + Spring Cache (本地缓存)           │   │
│  └────────────────────────────────────────────────┘   │
├──────────────────────────────────────────────────────┤
│                 基础设施层 (Infrastructure)             │
│  ┌────────────────────────────────────────────────┐   │
│  │   Docker + Nginx + Spring Boot JAR             │   │
│  └────────────────────────────────────────────────┘   │
└──────────────────────────────────────────────────────┘
```

### 2.2 核心设计原则

1. **前后端分离**：前端 SPA 通过 RESTful API 与后端通信，后端不关心视图渲染
2. **无状态认证**：JWT 令牌携带用户身份，服务端不维护会话
3. **RBAC 权限控制**：基于角色的访问控制，粒度到按钮级别
4. **审计追踪**：所有业务操作记录不可篡改的审计日志（哈希链）
5. **单表继承**：通过 role_hierarchy 实现科室子角色的权限继承

### 3.3 核心业务流程

#### 3.3.1 预约 -> 体检 -> 报告 完整流程

```
用户注册登录
    ↓
浏览套餐 → 选择分院 → 选择时段 → 填写信息
    ↓
创建预约（状态: CREATED）
    ↓
创建订单 → 模拟支付（状态: PAID）
    ↓
护士签到（状态: CHECKED_IN）
    ↓
采集体征（身高/体重/血压/心率/体温）
    ↓
科室队列排队（WAITING → CALLED → ARRIVED → COMPLETED）
    ↓ 各科室并行
    检验科（血常规等数值结果录入）
    影像科（X光/B超等文本结论录入）  
    内科/外科/眼科/耳鼻喉科/口腔科
    ↓
所有科室完成
    ↓
护士确认离场（COMPLETED）
    ↓
审核医生审核结果（通过/驳回）
    ↓
生成报告 → 填写诊断 → 终审签发 → 发送报告
    ↓
用户查看报告（含AI分析、趋势对比）
```

#### 3.3.2 状态机

**预约状态**: `CREATED → PAID → CHECKED_IN → COMPLETED / CANCELLED`

**订单状态**: `PENDING_PAYMENT → PAID → REFUND_REQUESTED → CLOSED`

**检查结果审核状态**: `PENDING → APPROVED / REJECTED`

**报告状态**: `DRAFT → PUBLISHED / APPEALED`

### 3.4 关键技术实现

#### 3.4.1 自定义 JWT 令牌
- 手写 HMAC-SHA256 签名算法（无外部 JWT 库依赖）
- Access Token 有效期 7200 秒（2 小时）
- Refresh Token 有效期 2592000 秒（30 天）
- `token_version` 字段实现账号禁用/改密后的令牌全局失效

#### 3.4.2 审计日志哈希链
- 每次写入审计日志时，用 SHA-256 计算 `hash = SHA256(前一条hash + 当前记录内容)`
- 提供 `AuditIntegrityService.verifyIntegrity()` 方法校验链条完整性
- 日志记录追加写入，不可篡改

#### 3.4.3 DeepSeek AI 趋势分析
- `TrendAnalysisService` 集成了 DeepSeek API
- 将历年体检数据构造为结构化 Prompt，调用 AI 生成趋势解读
- 结果缓存 1 小时，避免重复调用

#### 3.4.4 排队叫号策略
- 基于时段的优先级排序 + 空腹项目优先
- `DepartmentQueueService` 的 `callNext()` 方法实现叫号逻辑
- 由数据库状态字段 + 创建时间驱动

#### 3.4.5 角色层级
```java
ROLE_EXAM_DOCTOR_LAB > ROLE_EXAM_DOCTOR
ROLE_EXAM_DOCTOR_IMAGING > ROLE_EXAM_DOCTOR
ROLE_EXAM_DOCTOR_INTERNAL > ROLE_EXAM_DOCTOR
// ... 共 10 个科室子角色
```
所有科室医生 `@PreAuthorize("hasRole('EXAM_DOCTOR')")` 均生效。

### 5.3 架构原理

#### 5.3.1 认证流程
```
登录请求 → POST /api/v1/auth/login
  ↓
返回 JWT（含 roles 字段）→ 存入 localStorage (key: xixin_staff_token)
  ↓
导航守卫 beforeEach 解析角色 → 跳转对应首页
  ↓
护士 → /nurse/dashboard（排队看板）
医生 → /d/lab（其所在科室工作台）
审核医生 → /review/pending（待审核列表）
```

#### 5.3.2 登录态恢复
- `auth.init()` 在 App.vue mounted 时调用
- 从 localStorage 读取 token → 解码 JWT payload → 解析角色/分院/科室

## 11. 安全体系

### 11.1 安全架构总览

```
┌──────────────────────────────────────────────────────┐
│                    传输层安全                          │
│              HTTPS (TLS 1.3) + CORS                   │
├──────────────────────────────────────────────────────┤
│                    认证层                              │
│       JWT (HMAC-SHA256) + 双 Token 机制               │
│       Access Token (2h) + Refresh Token (30d)        │
│       token_version 全局失效                          │
├──────────────────────────────────────────────────────┤
│                    授权层                              │
│       RBAC + Role Hierarchy + @PreAuthorize          │
│       按钮级权限控制                                  │
├──────────────────────────────────────────────────────┤
│                    数据层                              │
│       BCrypt 密码哈希 + AES-256 字段加密              │
│       审计日志哈希链                                  │
├──────────────────────────────────────────────────────┤
│                    防护层                              │
│       Spring Security CSRF 禁用（API 无状态）         │
│       Nginx WAF 规则（生产环境）                       │
└──────────────────────────────────────────────────────┘
```

### 11.2 认证流程

```
用户登录
  ↓
AuthController.login()
  ↓
AuthService → BCryptPasswordEncoder.matches() 验证密码
  ↓
TokenService.generateTokenPair() → 生成 Access + Refresh 双令牌
  ↓
返回 { accessToken, refreshToken, expiresIn, userId, displayName, roles }
  ↓
前端存储到 localStorage（Web）/ uni.setStorageSync（App）
  ↓
后续请求 → Axios/fetch 拦截器 → Header: Authorization: Bearer <token>
  ↓
JwtAuthenticationFilter.doFilterInternal()
  ├── 提取 Token → TokenService.validateToken() 
  ├── 解析 payload → 构建 UsernamePasswordAuthenticationToken
  └── SecurityContextHolder.getContext().setAuthentication()
```

### 11.3 授权体系

**RBAC 层级结构：**
```
SYSTEM_ADMIN          → 全部权限
OPERATIONS_ADMIN      → 所属分院的运营数据
REVIEW_DOCTOR         → 审核/报告/健康管理
EXAM_DOCTOR_LAB   \
EXAM_DOCTOR_IMAGING  ├─ > EXAM_DOCTOR → 结果录入
...                  /
NURSE                 → 签到/体征/排队/采血/送检
NORMAL_USER           → 个人数据访问
```

**权限检查点：**
- 后端：`@PreAuthorize("hasRole('SYSTEM_ADMIN')")` 方法级拦截
- 前端：`v-permission` 自定义指令控制按钮显隐
- 数据级：`SecurityUtils.getCurrentBranchId()` 限制运营管理员的数据范围

### 11.4 数据加密

| 数据类型 | 加密方式 | 说明 |
|----------|----------|------|
| 登录密码 | BCrypt 加盐哈希 | Spring Security PasswordEncoder |
| 身份证号 | 应用层 AES-256 | 存储前加密，读取后解密 |
| 手机号 | 应用层 AES-256 | 存储前加密，读取后解密 |
| 传输 | TLS 1.3 | HTTPS 全站加密 |
| 审计日志 | SHA-256 哈希链 | 每条日志包含前一条的 hash，防篡改 |

### 11.5 审计追踪

- 所有 CRUD 操作通过 `AuditService` 记录
- 审计日志包含：操作人、操作类型、目标类型、目标ID、请求参数（脱敏）、响应结果、IP、User-Agent、Trace ID
- 哈希链机制：`entry_hash = SHA256(prev_hash + detail + timestamp)`
- `AuditIntegrityService` 提供全表校验方法

### 12.2 启动方式

**方式一：一键启动（start-all.bat）**
```batch
1. MySQL mysqld — 独立进程
2. mvnw spring-boot:run — Spring Boot 后端 :8080
3. npx vite — Admin 前端 :5173
4. npx vite — Staff 前端 :3000
```

**方式二：仅前端（start-front.bat）**
```
1. npx vite — Admin :5173
2. npx vite — Staff :3000
3. npx vite — User Web :8081
```

**方式三：Docker Compose（仅基础设施）**
```yaml
services:
  mysql:8.4 — root/root, database: xixin_health
  redis:7.2 — 端口 6379（预留，当前后端未使用）
```
